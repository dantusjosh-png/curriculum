# Foundations of Computing and AI

**Status:** Not started · **Est. length:** 8 modules ≈ 16 sessions

You build working systems with code and AI, but parts of the stack are a black box. This course opens the box: what's actually happening when your code runs, how to structure software so it doesn't rot, how to handle data cleanly, and how LLMs really work under the hood — so everything you build gets faster, sturdier, and less mysterious.

## Syllabus

| # | Module | Core question | Status |
|:--|:-------|:--------------|:-------|
| 1 | What the Machine Is Doing | Processes, memory, files, the interpreter — what actually happens when your script runs | Not started |
| 2 | Software That Doesn't Rot | Structure, interfaces, naming, dependencies — why codebases decay and how to stop it | Not started |
| 3 | Data Done Cleanly | Schemas, formats, pipelines, validation — trustworthy data handling | Not started |
| 4 | The Discipline Layer | Testing, debugging methodology, version control as a thinking tool | Not started |
| 5 | How LLMs Work I | Tokens, embeddings, attention, training — the actual mechanism | Not started |
| 6 | How LLMs Work II | Post-training, sampling, context windows — and exactly why they hallucinate | Not started |
| 7 | Engineering with AI | Prompting as programming, evals, agents, knowing when to trust output | Not started |
| 8 | Synthesis: Harden a Real System | Applying all of it to code you actually run | Not started |

**Capstone:** take one of your real, running tools and harden it end-to-end — restructure, add validation and tests, document it — with a written before/after postmortem of what was rotting and why.

## Positioning

Assumes: you write and ship working Python with AI assistance. Does not assume: CS degree. Bias: mental models that change how you build, over theory for its own sake; your own codebase is the lab.
